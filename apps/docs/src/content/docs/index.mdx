## Quick Example

```typescript
import { Monque } from '@monque/core';
import { MongoClient } from 'mongodb';

const client = await MongoClient.connect('mongodb://localhost:27017');
const monque = new Monque(client.db('my-app'));

monque.register<{ message: string }>('print-message', async (job) => {
  console.log(job.data.message);
});

await monque.initialize();
monque.start();
await monque.now('print-message', { message: 'Hello from Monque' });
```

See the [Quick Start](/monque/getting-started/quick-start/) for events, recurring jobs,
and graceful shutdown.

Add the [dashboard](/monque/dashboard/express/) to inspect jobs, filter and share views,

HTTP clients, with OpenAPI documentation, authorization, and payload redaction.

## Why Monque?

<CardGrid stagger>
  <Card title="Atomic Locking" icon="seti:lock">
      Multiple schedulers can share a jobs collection. Atomic claims prevent two workers from claiming the same pending job at once. Handlers must still be safe to retry.
	</Card>
  <Card title="Heartbeat Monitoring" icon="heart">
    Heartbeats record worker activity. During startup, Monque recovers processing jobs whose locks have expired.
  </Card>
  <Card title="Type-Safe" icon="seti:typescript">
		Use TypeScript generics to describe the payload each worker receives.
	</Card>
  <Card title="Framework Agnostic" icon="puzzle">
    Works with any Node.js framework and runs wherever you can connect to MongoDB.
  </Card>
  <Card title="Event-Driven" icon="comment">
		Record job starts, completions, and failures through event listeners.
	</Card>
  <Card title="Change Streams" icon="rss">
      Real-time job notifications via MongoDB Change Streams, while polling continues as a safety net.
	</Card>
  <Card title="Cron Scheduling" icon="seti:clock">
		Schedule recurring jobs with standard 5-field cron expressions. Automatic rescheduling after successful completion.
	</Card>
  <Card title="Exponential Backoff" icon="seti:clock">
    Automatic retries with configurable exponential backoff. Set retry limits and maximum delays for failed jobs.
	</Card>
</CardGrid>
