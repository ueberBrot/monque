---
title: Job Management
description: Read, filter, retry, cancel, reschedule, and delete Monque jobs in application code.
---

Use these methods on an initialized `Monque` instance. To expose them over HTTP, see the
[Management API](/monque/management/surface/). For a browser interface, see
[Dashboard setup](/monque/dashboard/express/).

## Read a job

[`getJob()`](/monque/api/classes/monque/#getjob) accepts a MongoDB `ObjectId` or its
hexadecimal string, including IDs returned by the Management API:

```typescript
const job = await monque.getJob('507f1f77bcf86cd799439011');
if (job) {
  console.log(job.name, job.status, job.data);
}
```

Missing jobs and invalid ID strings return `null`.

## Pagination

Use [`getJobsWithCursor()`](/monque/api/classes/monque/#getjobswithcursor) to read jobs in pages:

```typescript
const filter = { name: 'send-email', status: 'failed' } as const;
const sort = { by: 'createdAt', direction: 'desc' } as const;
const firstPage = await monque.getJobsWithCursor({ filter, sort, limit: 20 });

if (firstPage.hasNextPage && firstPage.cursor) {
  const nextPage = await monque.getJobsWithCursor({
    filter,
    sort,
    limit: 20,
    cursor: firstPage.cursor,
  });
  console.log(nextPage.jobs);
}
```

Keep the same filters and sort when following a cursor. To change either, start without a
cursor. Job names match exactly. Filters also accept multiple statuses and inclusive date
ranges for `createdAt`, `updatedAt`, and `nextRunAt`.

Sort by `identifier`, `createdAt`, `updatedAt`, or `nextRunAt`, in ascending or descending
order. A job ID breaks ties between equal timestamps. See
[`CursorOptions`](/monque/api/interfaces/cursoroptions/) for all options.

Cursor queries have a 30-second server execution limit. A cursor does not freeze the
collection: jobs may change or be deleted between requests.

## Metadata-only listings

Use [`getJobSummariesWithCursor()`](/monque/api/classes/monque/#getjobsummarieswithcursor) when
you do not need payloads:

```typescript
const page = await monque.getJobSummariesWithCursor({
  filter: { name: 'send-email' },
  limit: 50,
});

for (const job of page.jobs) {
  console.log(job._id, job.status, job.nextRunAt);
}
```

It accepts the same options and cursors as full listings, but excludes `data` from the
query and returned jobs. Load a job's payload with `getJob()` when needed.

## Single Job Operations

Pass a hexadecimal job ID to change or delete a job:

```typescript
const id = '507f1f77bcf86cd799439011';
const cancelled = await monque.cancelJob(id);
```

| Method | Eligible jobs | Result |
| --- | --- | --- |
| [`cancelJob(id)`](/monque/api/classes/monque/#canceljob) | Pending jobs | Sets status to `cancelled`. |
| [`retryJob(id)`](/monque/api/classes/monque/#retryjob) | Failed or cancelled jobs | Sets status to `pending`, clears failure state, and makes the job due immediately. |
| [`rescheduleJob(id, date)`](/monque/api/classes/monque/#reschedulejob) | Pending jobs | Changes `nextRunAt`. |
| [`deleteJob(id)`](/monque/api/classes/monque/#deletejob) | Any status | Permanently removes the document. |

Cancel, retry, and reschedule return the updated job or `null` if it is missing. An
incompatible state raises `JobStateError`. Repeated cancellation does not emit a second
`job:cancelled` event. Deletion returns `true` when a document was removed, otherwise `false`.
Deleting a processing job does not interrupt a handler that is already running.

```typescript
const nextHour = new Date(Date.now() + 60 * 60 * 1000);
await monque.rescheduleJob(id, nextHour);
```

## Bulk Operations

Bulk methods act on all jobs matching the selector, including jobs outside the current page:

```typescript
const cancelled = await monque.cancelJobs({ name: 'send-email' });
const retried = await monque.retryJobs({ name: 'send-email', status: 'failed' });
const deleted = await monque.deleteJobs({
  status: ['completed', 'cancelled'],
  olderThan: new Date(Date.now() - 7 * 24 * 60 * 60 * 1000),
});

console.log(cancelled.count, retried.count, deleted.count);
```

`cancelJobs()` only changes pending jobs. `retryJobs()` only changes failed or cancelled
jobs. `deleteJobs()` deletes every match. The selector's `olderThan` and `newerThan` bounds
apply to `createdAt`. An empty selector matches all eligible jobs.

Each method returns `{ count, errors }` and emits its corresponding bulk event. See
[`JobSelector`](/monque/api/interfaces/jobselector/) for selector fields.

## Queue Statistics

[`getQueueStats()`](/monque/api/classes/monque/#getqueuestats) returns counts for each status:

```typescript
const stats = await monque.getQueueStats();
console.log(stats.pending, stats.processing, stats.completed, stats.failed, stats.cancelled);

const emailStats = await monque.getQueueStats({ name: 'send-email' });
console.log(emailStats.total);
```

### Stats Caching

`statsCacheTtlMs` controls cached counts for both `getQueueStats()` and
`getQueueViewSummaries()`. The default is 5 seconds:

```typescript
const monque = new Monque(db, { statsCacheTtlMs: 10_000 });
```

Repeated reads can return cached counts until the TTL expires. Concurrent reads with the
same scope share a query, reducing database work when several clients request statistics.
Job management actions on this instance invalidate cached counts. Worker registration and
activity are read fresh, while changes from job processing or other instances may take up
to the TTL to appear in counts.

Set `statsCacheTtlMs: 0` to disable the cache. Concurrent reads still share a query.
Stopping Monque clears cached statistics.

## Queue View Summaries

[`getQueueViewSummaries()`](/monque/api/classes/monque/#getqueueviewsummaries) groups persisted
jobs and registered workers by job name:

```typescript
const views = await monque.getQueueViewSummaries();

for (const view of views) {
  console.log(view.name, view.stats.total, view.worker?.activeCount ?? 0);
}
```

Each summary includes counts, `hasPersistedJobs`, `hasRegisteredWorker`, and the local
worker's `concurrency` and `activeCount` when registered. Names are sorted alphabetically.
A name can appear with historical jobs but no worker, or with a registered worker and no
persisted jobs.

Pass `{ name: 'send-email' }` to scope the database aggregation and result to one exact
Job Name. Unknown names return an empty list; registered-worker-only names remain visible.
Filtered statistics use separate cache entries from the unfiltered overview.

Counts cover the MongoDB collection. Worker activity describes only the instance on which
you called the method, not all schedulers connected to that collection.
